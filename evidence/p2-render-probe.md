## 3. 渲染后 DOM：正文在 canvas 上，图片不可逐图取回

无头 Edge（`--headless=new`）+ CDP 取到的渲染 DOM（1 241 856 B）：

| 指标 | 值 | 含义 |
|---|---|---|
| `含三剑客` | **False** | 正文文字**不在 DOM**（在 canvas 上） |
| `<img>` | 11 | 全部是头像缩略图（`imageMogr2/thumbnail/180x180!`）、插件 logo、`blob:` URL |
| `<canvas>` | **1** | **正文由 WebOffice 引擎绘制在 canvas 上** |
| `background-image` | 162 处 | 正文排版用背景图，**无独立原图 URL** |
| 图片类 URL 引用 | 2（都是 wpscdn 的图标/关闭按钮） | 无正文图片直链 |

**结论**：正文图片**无法逐图下载**（canvas 像素 + blob: 对象）→ 图像内容只能以**页面像素（截图）**形式交给视觉模型。

## 5. 对规格的直接影响

1. **FR-12 必须新增渲染通道**（文字 + 截图素材包），**最终图文合并由 agent 侧用模型自带视觉完成**（形态 A）——插件是 host 侧代码，**调不到当前会话模型的视觉能力**。
2. 文字通道**择源判据必须可判定**：canvas 面积占比、API 文字命中编辑器 UI 噪声标记、API 文字过短。
3. 截图必须**跨页滚动**且**按屏高切图**（长图一次截全会让视觉模型精度下降）。
4. **渲染通道零 API 费用**（不调视觉 API），但**依赖本机 Edge**（Windows-only）。
5. 该文档的事实提醒收益边界：全文 3046 字里**只有第 1 战是文字**，第 2/3/4 战正文是图片 → 「图内文字化」的实际价值集中在这三部分。
